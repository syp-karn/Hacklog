## What I'm Building

A fast, scriptable web vulnerability scanner I can use during CTF assessments and real penetration tests. The goal is something I can kick off quickly with a target URL and get actionable output in under 60 seconds for most targets.

## Architecture Decisions

### Why asyncio?

Web scanning is I/O bound — most time is spent waiting for HTTP responses. `asyncio` + `aiohttp` means I can fire hundreds of requests concurrently without threading overhead.

```python
async def crawl(self, url: str, depth: int = 3):
    async with aiohttp.ClientSession() as session:
        queue = asyncio.Queue()
        await queue.put((url, 0))
        visited: set[str] = set()
        
        while not queue.empty():
            current_url, current_depth = await queue.get()
            if current_url in visited or current_depth > depth:
                continue
            visited.add(current_url)
            
            try:
                async with session.get(current_url, timeout=aiohttp.ClientTimeout(total=10)) as resp:
                    links = await self._extract_links(await resp.text(), current_url)
                    for link in links:
                        await queue.put((link, current_depth + 1))
            except Exception as e:
                self._log_error(current_url, e)
```

### Module design

Each check runs as an independent async module that receives a `Target` object and returns a list of `Finding` objects:

```python
class CheckModule(Protocol):
    async def run(self, target: Target, session: aiohttp.ClientSession) -> list[Finding]: ...
```

This makes it easy to add new checks without touching the core engine.

## Initial Benchmarks

Crawling a medium-size web app (PlaceholderApp, ~200 pages):

| Concurrency | Time | Requests |
|---|---|---|
| 10 workers | 47s | 214 |
| 50 workers | 12s | 214 |
| 100 workers | 9s | 214 |

50 workers is the sweet spot — higher concurrency starts hitting rate limits on most targets.
